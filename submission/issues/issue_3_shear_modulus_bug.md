## Missing shear modulus (Gs) fallback causes ValueError during programmatic .osi reload

When loading or re-running a saved `.osi` project file programmatically or via CLI (e.g., using `BridgeConfig.from_plate_girder_bridge`), the application raises an unhandled `ValueError` if the key `KEY_MATERIAL_GIRDER_G` is missing or empty.

```python
ValueError: Gs (shear modulus) is not set for grade 'E 350A'
```

---

### What is going on:

In `designer.py` (around lines 309–315), the code attempts to retrieve the shear modulus `KEY_MATERIAL_GIRDER_G` directly from `input_dict`. When a user designs interactively in the GUI, this key is populated by the GUI dialog. However, in saved `.osi` files generated by automated testing or standard exports, `KEY_MATERIAL_GIRDER_G` is sometimes omitted or left empty while Young's modulus (`E`) and Poisson's ratio (`nu`) are fully present.

Because there is no fallback calculation, the loader halts execution completely.

---

### Suggested Fix:

Add a standard isotropic elasticity fallback formula in `designer.py` (~lines 309–315):

```python
# In designer.py (~lines 309-315)
G_val = input_dict.get(KEY_MATERIAL_GIRDER_G)
if G_val is None or G_val == "":
    E = float(input_dict.get(KEY_MATERIAL_GIRDER_E, 200.0))
    nu = float(input_dict.get(KEY_MATERIAL_GIRDER_POISSON, 0.30))
    G_val = round(E / (2 * (1 + nu)), 1)  # standard isotropic elasticity fallback (76.9 GPa for steel)
    input_dict[KEY_MATERIAL_GIRDER_G] = G_val
```

This prevents crashes when loading exported project files or running headless batch simulations.
